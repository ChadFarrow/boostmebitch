# /demu Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `/demu` page: a search bar, then every self-hosted (non-Wavlake) album, newest track first, in week/month/year groups, with a date and an age on each row.

**Architecture:** `/api/demu` holds a server roster (one `/podcasts/bymedium?medium=music` call, cached 6 h, built by a pure `demuRosterRows`) and sends a slim list. `components/demu-page.tsx` sorts, groups, filters and pages it in the browser with pure functions from `lib/demu.ts`, pinned by `check:demu`. Two links lead to it from `/`.

**Tech Stack:** Next.js 15 / React 19, TypeScript strict, `node --experimental-strip-types` check scripts, headless Chrome over `scripts/cdp.mjs`.

**Spec:** `docs/superpowers/specs/2026-11-15-demu-page-design.md` (builds on PR #580, `docs/superpowers/specs/2026-11-15-demu-search-design.md`)

## Global Constraints

- Branch `feat/demu-page`, stacked on `feat/demu-search` (PR #580). PR base: `feat/demu-search` until #580 merges.
- `lib/demu.ts` stays **import-free** (not even `import type`); every new pure function goes there or in another import-free leaf. `lib/util.ts` keeps only type-only imports.
- A row is DeMu only through `isDemuFeed(row, closedService)` (fails closed on an absent `generator`), plus `dead !== 1`, plus one row per `podcastGuid`.
- `DemuAlbum` fields, exactly: `id, podcastGuid, title, author, image, artwork, url, medium, newestItemPubdate, episodeCount`. `medium` is always `'music'`. No `description`, no `generator`, no `v4vHint`.
- Group labels (data, rendered upper-case by CSS): `This week · Nov 9–15`, `Last week · Nov 2–8`, `Week of Oct 26`, `October 2026`, `2024`, `No date`. Weeks run Monday 00:00 to Sunday 24:00 in the **viewer's local time zone**; 8 weekly groups (this week + 7), then one group per month for the 12 months before the weekly window, then one per year.
- Age text: `upcoming` (future), `today`, `1 day`, `N days` (2–13), `N weeks` (14–59 days, ⌊d/7⌋), `N months` (60–364 days, ⌊d/30⌋), `1 year` / `N years` (⌊d/365⌋). Days are local calendar days.
- Date text: `Nov 14` in the current year, `Jun 1, 2024` otherwise (`en-US`).
- Page copy: heading `DeMu`; line `Self-hosted music. Nothing from Wavlake.`; count `1,163 DeMu albums` / `14 DeMu albums match “longy”`; no-match `No DeMu albums match “X”.`; not-loaded `Could not load the DeMu list.` + a `try again` button. The not-loaded state never reuses the no-match sentence.
- Entry points: `BROWSE DEMU` beside `♫ BROWSE PLAYLISTS` on `/`; `browse all DeMu →` beside the result count when the applied search type is `demu`. Nothing below the search input (`docs/ui.md`).
- No new `bmb:*` storage key. Phone first: 390 px, no horizontal overflow, targets ≥ 24×24 CSS px.
- Every push asks Chad (guard hook). No Podcast Index call storms: the browser test loads `/` at most twice.

## Review Focus

1. **`/api/demu` cold or failed** — the page shows `Could not load the DeMu list.` with `try again`, never `0 DeMu albums` or the no-match sentence. Pinned in Task 3's browser test by blocking `/api/demu` (CDP `Fetch.enable` failing the request).
2. **A ♥ pressed on `/demu`** — the saved favorite carries `medium: 'music'` (it reaches a shared kind:10333 event with no undo). Pinned in Task 4's browser test, signed out.
3. **Back from an album** — the search words, the rows shown and the scroll position come back. Pinned in Task 4's browser test.
4. **A viewer whose local day differs from UTC** — groups and ages use local time. Pinned by Task 1 vectors run under `TZ=America/New_York`.
5. **A Wavlake or dead or duplicate feed in PI's answer** — never reaches the page. Pinned by Task 1's `demuRosterRows` vectors and Task 2's API check (0 Wavlake generators, 0 `rssblue.com` URLs, unique guids).

**Interfaces:**
- Produces, all in `lib/demu.ts`:
  - `export interface DemuAlbum { id: number; podcastGuid?: string; title: string; author?: string; image?: string; artwork?: string; url?: string; medium: 'music'; newestItemPubdate?: number; episodeCount?: number }`
  - `export interface PiMusicRow extends DemuRow { id: number; podcastGuid?: string; title?: string; author?: string; image?: string; artwork?: string; dead?: number; newestItemPubdate?: number; episodeCount?: number }`
  - `export function demuRosterRows(rows: readonly PiMusicRow[], closedService: (url: string) => string | null): DemuAlbum[]` — drops `dead === 1`, drops rows failing `isDemuFeed`, projects to `DemuAlbum` (`image = row.image || row.artwork || undefined`; `artwork = row.artwork && row.artwork !== row.image ? row.artwork : undefined`; `title ?? ''`), then one row per `podcastGuid` (keep the newer `newestItemPubdate`, ties to the higher `id`; rows without a guid are all kept). Order of the output is not specified.
  - `export function sortDemuAlbums(albums: readonly DemuAlbum[], nowSec: number): DemuAlbum[]` — key `min(newestItemPubdate, nowSec)` descending, ties by `id` descending, no date last.
  - `export interface DemuGroup { key: string; label: string; albums: DemuAlbum[] }`
  - `export function demuGroups(sorted: readonly DemuAlbum[], now: Date): DemuGroup[]` — consecutive grouping of an already-sorted list; keys `w0`…`w7`, `m2026-10`, `y2024`, `none`.
  - `export function demuAge(sec: number | undefined, now: Date): string` and `export function demuDateLabel(sec: number | undefined, now: Date): string` (`''` when `sec` is undefined).
  - `export function matchesDemuQuery(album: Pick<DemuAlbum, 'title' | 'author'>, query: string): boolean` — trimmed, case-insensitive substring of title or author; an empty query matches.

- Produces: `export async function getDemuRoster(): Promise<{ albums: DemuAlbum[]; answered: boolean; fetchedAt: number | null }>` in `lib/pi.ts`; `GET /api/demu` answering that object as JSON.

- [ ] **Step 1: Implement the roster** — `DEMU_ROSTER_FRESH_MS = 6 h`, `DEMU_ROSTER_STALE_MS = 24 h`, `DEMU_ROSTER_COLD_WAIT_MS = 2500`, `DEMU_MAX_BYTES = 32 * 1024 * 1024` (comment: 9.9 MB measured 2026-11-15, room to grow). One call: `pi<any>('/podcasts/bymedium?medium=music', DEMU_MAX_BYTES)` → `demuRosterRows(data.feeds ?? [], closedService)`. One-entry bounded cache; one refresh in flight; a **failed refresh is never cached** and the last good roster keeps serving; a cold call waits up to the cold bound, then returns `{ albums: [], answered: false, fetchedAt: null }` while the refresh continues. Comments name the playlist roster as the pattern and say why each rule exists (copy the reasoning, not the prose).
