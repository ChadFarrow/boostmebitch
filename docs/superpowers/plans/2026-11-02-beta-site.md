# Beta Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve `main` plus a list of PR branches at `beta.boostmebitch.com`, so Chad can test several PRs together.

**Architecture:** `scripts/beta.mjs` rebuilds a local `beta` branch in a temporary worktree from `origin/main` and a list file stored on `beta`. It never pushes. A branch-scoped `NEXT_PUBLIC_BETA=1` turns on a `BETA` tag, `noindex` and a beta `site` value in bug reports. Vercel serves the branch through a branch-bound domain on the existing `boostmebitch` project.

**Tech Stack:** Node 24 ESM scripts, git, `gh`, Next.js 15 App Router, `scripts/cdp.mjs`, Vercel.

**Spec:** `docs/superpowers/specs/2026-11-02-beta-site-design.md`

## Global Constraints

- The script never pushes. It prints `git push --force-with-lease=beta:<sha> origin beta`, with the `origin/beta` sha the list was read from. Every push asks Chad (`workspace.md` rule 7).
- `beta` never merges into `main`.
- The list file is `.beta-branches`, and it exists only on `beta`.
- The list comes from `origin/beta`, so both machines read the same list.
- `NEXT_PUBLIC_BETA` means on only for the exact value `1`.
- `BRAND.domain` does not change. Keysend, notes and NIP-05 read it.
- The `BETA` tag takes no space from `<AppHeader>` (38px height limit, no spare width at 390px). It stays below `z-[70]`.
- `CLAUDE.md` is at 15000 of 15000 words. Each edit there must be word-neutral. `npm run check:claudemd` must pass.
- Add `package.json` lines directly after `"typecheck"`. The end of the `e2e:*` list is where open PRs add lines, and a line there makes them conflict.
- Stage files by path. The untracked `.claude/` folder stays out of every commit.
- No value of a secret variable appears in a command line, a log or a chat. No attribution lines in commits or PR bodies.
- Read `docs/ui.md` before the bug report and layout edits, and `docs/testing.md` before a build or an e2e run.

## Review Focus

Each line has its test in the task that owns the code.

1. Chad runs the script with uncommitted work on another branch: the checkout and its files do not change (Task 1).
2. A PR is squash-merged and its branch still exists: the entry leaves the list with a note, and no false conflict appears (Task 1).
3. A second `add` runs before the first rebuild is pushed: the output warns that the unpushed list is replaced, so the loss is not silent (Task 1).
4. The e2e test opens the bug report on the real beta address: it must not file a public issue, so it stubs `/api/bug-report` in the page (Task 2).
5. A phone in the installed app has no address bar: the tag shows with a modal open, blocks no touch and adds no sideways scroll (Task 2).

- [ ] **Step 4: Implement `scripts/beta.mjs`**

The header comment gives the reason for each rule below. The order of work is load-bearing:

1. `git fetch --prune origin`. Stop on failure.
2. Stop if `git cat-file -e origin/main:.beta-branches` succeeds: `beta` reached `main`.
3. Stop if `git worktree list --porcelain` shows `refs/heads/beta` checked out.
4. Read the list from `origin/beta:.beta-branches`, or start empty when `origin/beta` does not exist. Warn when a local `beta` differs from `origin/beta`.
5. `list` prints and exits here.
6. Apply `add` and `drop`. A number resolves through `gh pr view <n> --json headRefName,isCrossRepository,state`. Refuse a fork PR, a PR that is not `OPEN`, `main`, `beta`, a name with no `origin/<name>`, and a `drop` of a name not on the list. An `add` of a listed name prints a note and changes nothing.
7. Prune. For each entry, read `gh pr list --head <b> --state all --json state,number`. Keep the entry if any PR is `OPEN`. Remove it with a printed note if not, and any PR is `MERGED`. Keep it otherwise. A `gh` failure stops the run, because a wrong answer here gives a false conflict. An entry that stays and has no `origin/<b>` stops the run.
8. In `mkdtemp(tmpdir()/bmb-beta-)`, run `git worktree add --detach <dir> origin/main`. Merge each `origin/<b>` with `git merge --no-ff --no-edit -m "beta: merge <b>"`. On a conflict, print the branch and `git diff --name-only --diff-filter=U`, run `git merge --abort`, and exit 1.
9. Write `.beta-branches` and commit it as `beta: <n> branches`, with the list in the body.
10. `git branch -f beta <sha>`, then print the list and the push command as the last line.

A `finally` runs `git worktree remove --force <dir>` and `git worktree prune` on every path.
