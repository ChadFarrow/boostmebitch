# CLAUDE.md

**How to read this file.** Each entry is a rule plus one clause naming the consequence of breaking it; "this shipped broken once" is evidence the obvious version is wrong, not an invitation to re-litigate. **The reasoning lives in `docs/`, indexed below, and the `→` at the end of an entry points at it** — follow it before you edit in that area. The README at the repo root is the architecture spec.

**What lives here vs `docs/`.** Only what must be in mind *before* you know which file you're opening: money-path and security invariants, boundaries, repo-wide conventions, stop-ship checks. **A new rule goes in the relevant `docs/` file unless it (a) can lose funds or leak a credential, (b) governs where code may go, or (c) applies to edits in files you haven't opened yet** — and even then as a rule plus a pointer, never a narrative. Without that test this file grows back (it reached 26,000 words once), which is why `npm run check:claudemd` measures it.

## Report in ASD-STE100 Simplified Technical English

Write every chat reply to the user in **ASD-STE100 Simplified Technical English (STE)** — short active sentences, one instruction per sentence of at most 20 words, simple tenses, one word per meaning; the full rules are in the user's global `~/.claude/CLAUDE.md`. It is a rule about your OUTPUT and covers **chat prose only**: not code, comments, commit messages, PR titles or bodies, or `docs/`. Keep identifiers, file paths, commands, log lines and quoted tool output verbatim, and technical names (`keysend`, `boostagram`, `valueTimeSplit`, `sanitizer`) as they are.

## Names

**Every one of these is PER-BRAND and lives in `lib/brand.ts`. Never hard-code one — import `BRAND`.** One repo builds two deploys — `boostmebitch.com` (`NEXT_PUBLIC_BRAND` unset) and the family-friendly `boostmebuddy.com` (`NEXT_PUBLIC_BRAND=buddy`) — and **two Android apps, of which only `com.boostmebuddy` is listed on Zapstore**; a TWA wraps an ORIGIN, so a package id can never be rebranded after its first publish. A hard-coded name is the other brand's word on the family-friendly site, in a boostagram an artist's aggregator prints, or in the `client` tag of a public kind:1 that can never be edited. Pinned by `npm run check:brand`.

- **`boostmebitch` / `boostmebuddy`** — repo and npm package name (the repo keeps the original). `BRAND.userAgent` (`<wireName>/<version> (+<origin>)`) is every server request's `User-Agent`; no literals.
- **"Boost Me Bitch" / "Boost Me Buddy"** — `BRAND.displayName`: the page header and `<title>`.
- **`BoostMeBitch` / `BoostMeBuddy`** — `BRAND.wireName`: `app_name` in the boostagram TLV JSON, the `client` tag on Nostr notes, and the `via <app>` ending every boost note's sentence, read from `app_name` (CamelCase, no spaces — matches the Helipad-aggregator convention used by Fountain, StableKraft, etc.). The two deploys identify themselves separately on purpose, so a recipient can tell which site paid them. **Except a boost NOTE for a playlist hosted on the Buddy origin**: it wears Buddy's words, tag, `via` and site key on either deploy (`noteBrandFor`); its boostagram still names the payer. **`clientTag()` builds it for every publisher**, because a second copy fails by going MISSING, which no type catches. **`sendZap`'s kind:9734 carries none on purpose**: the recipient's LNURL server reads it before any relay does, so a tag there is a money-path change.
- **`SITE_NOSTR_SK` — a DIFFERENT KEY PER DEPLOY, its npub pinned as `BRAND.siteNpub`.** It signs a signed-out or Anonymous boost note, so one shared key puts the other brand's name and nip05 on every family-friendly note. `scripts/publish-site-profile.mjs` refuses a key that does not derive the active brand's npub. **Vercel stores both as *sensitive*, which nothing can read back** — the owner types each into `.env.local` / `.env.buddy.local`; never ask for one in chat.
- **`BRAND.iconDir`** — its `icon-512.png` is also the site kind:0 `picture`, the TWA `iconUrl` and the Zapstore icon, so a rename blanks the site's avatar on every client until `publish:site-profile` runs again. → [`brand/README.md`](brand/README.md)

**`lib/brand.ts` is an import-free leaf and must stay one**; it holds `DEFAULT_SENDER_NAME` and `resolveSenderName`. → [`docs/money-boosts.md`](docs/money-boosts.md)

**Three things are deliberately NOT per-brand, and each would destroy data if branded.** The kind:30078 d-tags `boostmebitch:wallet:spark`, `boostmebitch:wallet:nwc` and `boostmebitch:settings` are addressable at the **user's** pubkey, so one person using both deploys opens ONE wallet backup; branding them points the new deploy at an address nothing ever wrote, and every backup reads back as *"No backup found on Nostr for this account"* — intact, unreachable, reported as never having existed. The `bmb:*` `localStorage` prefix stays too.

**They are PURE-FUNCTION pins, and the wiring BETWEEN them is where this repo's bugs live.** No `check:*` sees a cycle that never decrypts, a planner answering "nothing changed" about a half it could not read, or a hydrator recording a baseline for a publish it refused: all three shipped on one branch and were found only by driving the real app against a real signer and relay — `npm run e2e:favorites`. **`services/nostr-index` has its own checks and this repo's `check:*` do not run them** — `cd services/nostr-index && npm run typecheck && DATABASE_URL=... npm run verify`. → [`docs/nostr-index.md`](docs/nostr-index.md)

**The import-free arrangement is enforced, not just documented.** Each module a check loads under plain Node (`favorites-list.ts`, `read-trust.ts`, `lease.ts`, `brand.ts`, `site-stamp.ts`, `community/rules.ts` and the other leaves) must have no imports; `nwc-errors.ts`, `favorites-export.ts`, `relay-socket.ts`, `boost-echo.ts`, `community/{clean-text,guest-key}.ts` and `v4v/lnurl-bech32.ts` may import bare npm packages only. `scripts/import-free.mjs` scans for it, every check pinning one calls it, and **it rejects type-only relative imports too** (type-stripping erases them, so only the scan sees a module one `type` deletion from breaking). **`mute-state.ts` shows the rule shapes the code**: `MuteCipher` and `classifyMuteContent` live beside `MuteListState`, because a second leaf would need an `import type`.

Each check **imports the real module** via `node --experimental-strip-types`: a copy passes green while shipping code drifts. Each carries a *must-still-work* half: over-blocking is a regression too. **Vectors were generated by the shipping code; if one fails, fix the code — never edit the vector to match.**

**Build a fixture from the WIRE, not the struct you parse it into, and check a new vector fails against something before you keep it** — a round-trip built from your own fields cannot fail, which is how `check:favsync`'s vector named "lossless" sat green while every publish dropped what another app wrote past position 3. Run it against the old implementation first, else the *obvious wrong* one: `naive()`.

**Make the replay TOTAL, not a hand-written second list** — `check-assetlinks.mjs` named six of twenty-nine, so a section sat green against nothing. Vectors are recorded as **calls** (`{ kind, args }`) and the replay walks the list; the must-still-work half is exempted one vector at a time with `{ alsoNaive: true }`, **a CLAIM that `naive()` still agrees, which `scripts/replay-vectors.mjs` asserts** (three exemptions were hiding faults).

**`npm run check:claudemd`** guards this file's size and completeness (budget in the script), and **`check:conformance`** runs the spec's 31 vectors against the favorites merge (needs `../PC20-Nostr` or `PC20_NOSTR_DIR`). Neither pins a pure function. **`npm run check` runs every `check:*`** (conformance reported, never gating); **run it with typecheck/lint/build before shipping.**

**Stop the dev server before `npm run build`, and `rm -rf .next` before starting `dev` again** — the collision runs BOTH ways, and the dev-side symptom is a React Refresh error that reads as an application bug.

**"Testing locally" and "testing against local data" are DIFFERENT THINGS.** A dev server on localhost still publishes to the public relays under whatever npub is signed in — including the shared kind:10333 event, which keeps no history. A session touching favorites, mutes, follows or the profile uses `npm run relay`, `npm run seed:relay -- <npub>`, `npm run e2e:favorites` or `npm run e2e:mutes` — never a real account. **A branch "N commits ahead of `main`" is NOT unfinished work**: a squash merge changes the patch id, so ask `gh pr list --state merged`. → [`docs/testing.md`](docs/testing.md)

**A change to what a community playlist FEED contains goes to `main`, even while the maker is beta only.** Production serves every published feed (`COMMUNITY_FEEDS=on`) and beta answers a feed URL with a `301` to it, so a feed change on a beta-only branch reaches no app. → [`docs/feeds.md`](docs/feeds.md)

**Re-landing a REVERTED feature: compute what the revert touched — the conflict list will not.** A merge conflicts only where BOTH sides changed a file, so a revert's deletions land unopposed, on a green build. → [`docs/ops.md`](docs/ops.md)

## Server vs client boundary (don't cross it)

Podcast Index credentials must never reach the browser. Enforced by file conventions, not bundler config.

**Server-only:** `lib/pi.ts` (`node:crypto`, `process.env`), imported by `app/api/*` and by `app/page.tsx`'s `generateMetadata` — both server-side, but the rule is not "API routes only"; the BoostBox proxy `app/api/lightning/boostbox/route.ts` (`BOOSTBOX_URL`/`BOOSTBOX_API_KEY`); `app/api/gifs/route.ts` (`GIPHY_API_KEY`); `lib/safe-fetch.ts`; `lib/rate-limit.ts` (per-IP, first line of every API route); **`lib/playlist-db.ts`** (`pg`, `PLAYLIST_DB_URL` — read-only, reverts to PI on failure); `lib/community/` except import-free leaves and browser-only `client.ts`, `guest-key.ts` and `use-guest-key.ts`; the note stamp's `lib/stamp-address.ts`, `lib/site-stamp-server.ts`, `lib/site-sign-template.ts`.

**Browser-only:** `lib/store.ts`, `lib/v4v/nwc.ts`/`webln.ts`/`lnaddr.ts`/`spark.ts`/`boostbox.ts`, `lib/nostr/`, `lib/storage.ts`, `lib/podcast-meta.ts` — they touch `window.*`, storage, IndexedDB, or WASM. SSR guards exist but assume client context.

**Isomorphic:** `lib/types.ts` (pure types), `lib/v4v/boost.ts` (orchestration).

**A THIRD place is not part of this app: `services/nostr-index/`** — a separate Railway deployable with its own `package.json`, because it holds relay WebSockets open and a serverless function cannot. It is excluded from `tsconfig.json` and `eslint.config.mjs`, so **`npm run typecheck` and `npm run lint` do not cover it**. It never imports from `lib/` and `lib/` never from it (the relay lists and NIP-73 prefixes are deliberately duplicated); the app reaches it only through `lib/nostr-index-server.ts`, server-side.

**It does NOT deploy when you merge.** The Railway service is CLI-uploaded: merging to `main` deploys the Vercel app and leaves the index on whatever was uploaded last. `railway up` from `services/nostr-index`, **then read the DEPLOY log for the package name** (the build log never prints it): `boostmebitch-nostr-index`, never `boostmebitch`. **`railway up` uploads the nearest git ROOT** (from a worktree, the main checkout), so ship a merged commit as a `git archive` export outside every repo. → [`docs/ops.md`](docs/ops.md), [`docs/nostr-index.md`](docs/nostr-index.md)

Components fetch via local API routes (`fetch('/api/feed?id=…')`) — never call PI directly.

## Cross-cutting rules

Each of these has cost something real, and you can break it from a file that looks unrelated. **The rule is here; the reasoning is behind the pointer.**

### Security and hostile input

- **A parser returning `null` is NOT a safe default at any call site that then reaches the network — an input that accepts a Nostr identifier must reject an `nsec` explicitly, before the fetch.** `parseNpubInput` returns `null` for a key *and* for junk, so a pasted key fell through to our server logs and Podcast Index; **a key sent to a third party is burnt**, so every box whose text leaves for one (the GIF search too) refuses it, with a **prefix** test (`looksLikeSecretKey`) before any decode and a **rendered** refusal. → [`docs/security.md`](docs/security.md)
- **`safeUrlAttr` is a scheme ALLOWLIST and must stay one** — as a denylist it let six vectors reach the DOM as live `javascript:`, and this origin's `localStorage` holds a spending credential. → [`docs/security.md`](docs/security.md)
- **Every server-side fetch of a feed/chapter/transcript URL goes through `safeFetch(url, init)`, never a bare `fetch`** — it re-validates every redirect hop and resolves each hostname, because an IP-literal check is beaten by a public DNS record (`http://127.0.0.1.nip.io/`). → [`docs/security.md`](docs/security.md)
- **Read any third-party body — server OR browser — with `readCappedText`/`readCappedJson` (`lib/capped-body.ts`), never bare `res.text()`/`res.json()`.** `AbortSignal.timeout` caps how LONG a fetch runs, not how many bytes it returns. A new module-level cache of feed content needs a size ceiling and eviction too. → [`docs/security.md`](docs/security.md)
- **Read a feed attribute with `readAttr` (`lib/feed-xml.ts`), never a local regex or `\b`** — it matches `x-address`, and `address='…'` inside another value, so a decoy steers the payee unseen (`check:feedxml`). **And walk a document with `findBlocks`/`findTags`, never a `[\s\S]*?` or `<tag\b[^>]*>` regex** — each is O(n²) on repeated unclosed opens (`check:feedscan`). → [`docs/security.md`](docs/security.md)
- **A feed-supplied URL rendered as an `href` goes through `httpUrl` at the PARSE boundary — `safeUrlAttr` guards show-notes HTML and nothing else.** React does not block a `javascript:` href, it only warns in dev, and this origin holds the NWC credential and the nsec — so `<podcast:funding url>` put a live script link under the SUPPORT button. Three sources arrived unguarded: funding (from RSS *and* from PI, which mirrors the author's string verbatim), a chapters JSON `url`, and BoostBox's `url`, which is also persisted into `StoredBoost.legs` — so **disk is a second parse site** (`coerceStoredBoost`): an entry stored before the guard outlives it. Guard at the parse site so a fourth surface inherits it. → [`docs/security.md`](docs/security.md)
- **Read a REQUEST body with `readCappedRequestJson`/`readCappedRequestText` (`lib/api-handler.ts`), never `req.json()`/`req.text()`** — those buffer first and measure after, and `/api/nostr/site-sign` is unauthenticated at 30/min. They return `null` rather than throwing, so the route answers its own 400. → [`docs/security.md`](docs/security.md)
- **A route's unhandled 500 returns its `fallback`, never `e.message`** (`lib/api-handler.ts`): `PiHttpError` carries PI's raw body and `assertSafeFetchUrl` names the host it rejected, so reflecting the message turns the SSRF guard into an oracle. → [`docs/security.md`](docs/security.md)
- **The bug report files a PUBLIC issue under the owner's name from an unauthenticated POST.** Its snapshot is an ALLOWLIST (`APP_INFO_KEYS`) and `secretInReport` refuses an nsec or NWC string, in the modal AND the route; never add a field carrying an npub, key, connection string, balance or URL query, and never interpolate issue text into `user-report-notify.yml`. **A report Chad sends while an agent debugs that problem with him is closed when the fix merges, with a comment naming the PR and the build that has it.** → [`docs/ui.md`](docs/ui.md)
- **`/api/og/boost.png`'s path, parameter names and `.png` suffix are a PERMANENT PUBLIC CONTRACT — never rename or repurpose one.** Every boost note writes that URL into a signed kind:1 that cannot be edited, so a rename blanks the picture on all of them. Add parameters; never change one's meaning. → [`docs/nostr.md`](docs/nostr.md)
- **The Digital Asset Links statement delegates this ORIGIN to an Android package — never publish a fingerprint or package id you did not build** (a verified TWA gets the profile that holds the NWC credential and the nsec). An unset or malformed value yields an **empty statement list, never a guess**; `force-dynamic`, `Cache-Control: no-store` and the release workflow's live-statement check are not removable. **`public/manifest.json` is read by Bubblewrap too**: editing `name`/`scope`/`start_url`/`orientation`/`icons` changes the next Android build. → [`docs/android.md`](docs/android.md)

### Money and payment rails

- **"My boost didn't show up" is NOT, on its own, evidence about this code — establish which RAIL its legs took before opening a file.** A keysend carries the boostagram inline in TLV `7629169`; an LNURL leg carries none, only the `rss::payment` descriptor in the LUD-21 comment. Measured causes, none in the payment code: the wallet cannot keysend (Spark is BOLT11-only), the leg was retried onto LNURL, the receiving tool was broken. Read the `[keysend]`, `[lnurl]` and `[boostbox]` console lines **first**, and **do not write down what a receiving tool does with a leg**. → [`docs/money-boosts.md`](docs/money-boosts.md)
- **An `Episode` rebuilt from storage keeps the `id` it was LISTED under — `id` is a money key, not a React key.** `/api/value-splits`, the streaming split cache and every boostagram `itemID` read it; downloads rebuilt it from the feed id, so every song window streamed to the host (`downloadEpisodeId`, `check:downloads`). → [`docs/downloads.md`](docs/downloads.md)
- **Read an LNURL-pay endpoint with `lnurlFetch` (`lib/v4v/lnurl-fetch.ts`), never a bare `fetch`.** It tries the provider directly and falls back to `/api/lnurl` only when the browser **throws**, keeping our server and the typed message out of the money path. LNURL is the one rail every wallet supports, so a blocked read fails the leg on NWC, WebLN and Spark at once; the retry is safe only because an invoice request mints a BOLT11 that expires unpaid. → [`docs/money-boosts.md`](docs/money-boosts.md)
- **Every `client()` in `lib/v4v/nwc.ts` opens a WebSocket and MUST be closed in a `finally`.** nostr-tools does not dedupe relays by URL and `executeNip47Request` closes only its subscription, so an unclosed client strands a half-open socket against the relay's connection cap: four of six call sites leaked, **the wallet paid while every leg reported failure**, and a reload cleared it. → [`docs/wallets.md`](docs/wallets.md)
- **The rail picker stays in BOTH boost modals** (`components/rail-picker.tsx`): picking silently via `pickRail()` sent boosts out of an old WebLN extension while a funded Spark wallet sat untouched. **A surface that renders it must subscribe to EVERY rail `availableRails()` reads — a rail with no subscription is unofferable, not merely stale** — and **adding a rail means adding it in `useWalletChange` too.** → [`docs/wallets.md`](docs/wallets.md)
- **A CONTAINER FEED IS NOT ALWAYS THE PARENT OF THE ITEMS IT LISTS — never copy the container's `url`, `medium`, title or art onto an item whose `podcastGuid` names a different feed.** A `musicL` **playlist** lists tracks in hundreds of OTHER feeds, so those would be published as facts about the TRACK, to a shared kind:10333 event, **with no undo**. The guard is `containerIsParent` INSIDE the component, never a prop (a prop is what a future surface forgets to pass). **Three money sites**: `paymentIds`' HOST_BUCKET branch, the boost modal's `remote_feed_guid`, and the payment itself; `payableValue` (`lib/util.ts`, `check:musicl`) is the one expression and refuses NARROWLY — both guids must be present to disagree. → [`docs/money-boosts.md`](docs/money-boosts.md)
- **Artwork goes through `/api/art`, and the RAW third-party URL must stay in `artCandidates` behind the proxied one**: the `onError` ladder falls through to it, so a failing route costs speed only, while dropping the tail blanks every cover on twelve surfaces. **The width is an allowlist, never a free integer** (each `(url, width)` is a CDN cache key), and **`Content-Type` is not the boundary** — `safeFetch`, the byte cap, `limitInputPixels` and sharp's magic bytes are. **The proxy takes frame one**: only the fullscreen big cover takes the published file (`preferOriginal`, on `open && artOk`) and the lock screen lists ONE entry. → [`docs/ui.md`](docs/ui.md)
- **A per-IP limit that fans out per LIST ITEM must be sized against a real list, and a 429 is never an answer about the data.** `/api/by-guid` and `/api/episode-by-guid` issue one request per favorited show and track (~213 and ~232 on a cold hydration; a phone and desktop share one household IP). `lib/podcast-meta.ts` once negative-cached every non-ok status as "PI does not hold this feed" **for the life of the tab**; `COULD_NOT_ASK` (429, 408) now returns an **uncached** null and does *not* trip the PI breaker. → [`docs/feeds.md`](docs/feeds.md)
- **A Podcast Index "not found" must reach the client as 404, never 500.** **PI signals not-found with HTTP `400`**, so every `lib/pi.ts` wrapper turns 400/404 into `null` **in the wrapper, not the route** (the route cannot tell a miss from an outage; auth/5xx must still propagate). A 5xx trips the client-side breaker and disables *all* metadata resolution for the tab: one unindexed music feed took **227 favorites to 0**. → [`docs/feeds.md`](docs/feeds.md)
- **A route that fans out to PI must cap the fan-out, and the cap belongs on any list that came from a feed** — an attacker-chosen length otherwise turns one request into N parallel PI calls (`/api/publisher` slices to `MAX_PUBLISHER_ALBUMS`). Follow probe-first-then-batch and let the probe throw, except a 429/408, which `withErrorHandling` answers verbatim so the client breaker stays shut. → [`docs/feeds.md`](docs/feeds.md)

### Signers and secrets

- **`nostr-tools` is pinned to exact `2.19.4` — do NOT bump it or relax the caret.** `2.20.0+` breaks `nostrconnect://` login (2.25.2 included), so its leaked-socket fix is ours (`lib/nostr/relay-socket.ts`): **build a pool with `newPool()`, never `new SimplePool()`**. A bump must re-run `verify:yield` (2.19.4 leaks a `MessagePort` per message in Node, `src/node-yield.ts`), and **that fix must not be ported to the browser** (React's scheduler reads `MessageChannel`; the `setTimeout` fallback clamps the drain, #313). → [`docs/signers.md`](docs/signers.md)
- **`bmb:amber_pending` and `bmb:amber_result` reach DISK, so neither may ever hold a secret — and `AMBER_PERSISTABLE_TYPES` is not the same list as `RESUMABLE_TYPES`.** They are localStorage because Brave opens Amber's callback in a **new tab**; `storage.amberResult.set` writes nothing outside `AMBER_PERSISTABLE_TYPES` (today just `get_public_key`). The lists answer *is this result safe on disk* versus *can this request afford a page reload*; merging them would let `nip04_decrypt` write the user's plaintext to disk. → [`docs/signers.md`](docs/signers.md)
- **"Amber didn't come back" is NOT, on its own, evidence about this code — three other causes show the same screen.** (1) Amber splits the `nostrsigner:` URI on `?` BEFORE parsing, and **every boost note carried two**, so `AmberSigner.signEvent` writes `?` as `\u003f`. (2) Chromium stopped stamping `Browser.EXTRA_APPLICATION_ID` (2026-08), so the request goes out as an `intent:` URL via `buildSignerIntentUrl`. (3) A **stale queued Amber request**: `adb shell am force-stop com.greenart7c3.nostrsigner` before believing one. → [`docs/signers.md`](docs/signers.md)
- **A plaintext handed to an external signer must contain no `?`, and who READS it picks the fix (`lib/nostr/amber-safe-text.ts`).** JSON another app reads uses `escapeJsonForAmber`; a plaintext ONLY this app reads uses `encodeAmberSafe`; percent-encoding is neither (Amber decodes the `%3F` back into the character it splits on). An **NWC connection string is structural** (NIP-47 writes `?relay=`): **every NWC backup attempted on Android failed**, silently. `payloadSurvivesAmber` is a predicate, not an assertion, because `publishBoostNote` signs *after* the sats have moved. **A new coordinate's reader must accept the un-encoded legacy form.** → [`docs/signers.md`](docs/signers.md)
- **Never make an external signer render a secret the user did not ask to see — `decryptWithTimeout`'s `purpose` argument is required, and every caller above it must PASS IT THROUGH rather than hardcode one.** Amber's approval sheet shows the DECRYPTED PLAINTEXT, and `doLoadProfile` read three encrypted-to-self coordinates on every cold start, putting twelve BIP-39 words full-screen on a Pixel 6. Callers gate on `unattendedDecryptOk()` and the library refuses an `'unattended'` decrypt as a backstop; the parameter only forces a decision at the layer that has it (`fetchEncryptedMnemonic` hardcoded `'unattended'` and overrode every caller). → [`docs/signers.md`](docs/signers.md)
- **"Is this signer inside the browser?" is `unattendedDecryptOk()` (`lib/nostr/signer.ts`), and the answer is TWO signers, not just Amber — never re-derive it as `!isAmberActive()`.** Everything stored encrypted-to-self is read on page load, so the gate is a privacy decision; a NIP-46 bunker on the user's OWN PHONE (Clave, Amber-as-bunker, nsec.app mobile) answers inside the device. **`listDecryptOnLoadOk(npub)` widens it for the favorites and mutes halves ONLY**, on a flag set by pressing unlock. **It reads the PERSISTED signer kind, not `window.nostr`**, and is not interchangeable with `canSignUnattended()`, which answers false at cold start for a local-key user. → [`docs/signers.md`](docs/signers.md)
- **A REJECTION FROM A BUNKER IS NOT EVIDENCE THE TRANSPORT IS DEAD — an error RESPONSE proves the round trip worked.** nostr-tools 2.19.4's `nip46.js` rejects with the signer's error **string** while every other rejection on that path is an `Error`, so `!(e instanceof Error)` means "the signer answered". **One answer means *not yet*: some signers reply `permission denied` first, on an id `nip46.js` drops, so `bunker.ts` re-issues; not the decrypts.** **Every app holding the key answers, so a result beats an error on one id** (`holdErrorsForResult`). Both rest on the `2.19.4` pin. → [`docs/signers.md`](docs/signers.md)
- **Publish a signer's `nostrApi`, never the signer instance** — `private sk` has no runtime effect, so the instance exposes the raw key as `window.nostr.sk` to every script on the origin. No key-export method on `LocalSigner`, no module-level accessor returning the key; the prohibition is on *ambient* reach (`<ExportKeySection>` reveals the nsec on an explicit click, gated on `storage.signer.get() === 'local'`, and that is the only carve-out). → [`docs/signers.md`](docs/signers.md)
- **Cap every signer decrypt with `withDecryptTimeout` (`lib/nostr/signer.ts`) — a NIP-07 extension that goes away does not reject, it HANGS** (iOS Safari kills its background mid-query: no rejection, nothing in the console). The mute list's private half is a bare NIP-04 decrypt whose caller swallows failures, so the whole list disappeared in silence; the timeout converts a hang into the branch the code already handles. → [`docs/nostr.md`](docs/nostr.md)

### Publishing to relays

- **Never publish a kind:3 follow list you didn't reliably fetch, and never record it as published without `assertPublished`.** A blind republish wipes the user's whole follow list; an unasserted one promotes a list no relay holds to `storage.follows`'s last-known-good. `publishFollow` shipped without the assert. → [`docs/nostr.md`](docs/nostr.md)
- **`publishSignedEvent` resolving is NOT proof anything landed** — it uses `Promise.allSettled` and never rejects, so `acceptedRelays` can be `[]`. A caller recording durable state on the strength of a publish gates it on `assertPublished(note, what)` (`lib/nostr/publish.ts`), in the feature's own wrapper: the favorites baseline shipped without it, so a favorite that reached nobody **was never published again** while the UI reported success. → [`docs/nostr.md`](docs/nostr.md)
- **Same for kind:0 — merge an edit over `fetchRawProfile`, never over `ProfileMetadata`, and never publish an untrustworthy read.** `fetchProfile` returns a seven-field whitelisted subset, so a profile rebuilt from it silently deletes `banner`, `website` and every field another client set. Both writers go through `publishProfile`. → [`docs/nostr.md`](docs/nostr.md)
- **The private half of the mute list is NOT NIP-04 — it is whatever the writer used, and `classifyMuteContent` decides that from the bytes before any signer is asked** (NIP-51 moved private items to NIP-44; some clients leave the tags in the clear). `MuteListState.privateCipher` carries the observed cipher to `publishMuteList`, which re-encrypts in the form it read — NIP-04 over a NIP-44 list makes it unreadable to the client that wrote it. **A new field on that state must be added to `coerceToMuteState` and to the hand-listed `merged` object in `mutes-hydrator.ts`**, or it is dropped on every reload. Pinned by `check:mutes`. → [`docs/nostr.md`](docs/nostr.md)
- **Never record an absence you didn't reliably observe, and don't take the relay library's word for it.** `fetchLatestEventDetailed`'s `trustworthy` tells "nobody had it" from "nothing answered". **Do not compute it from nostr-tools' aggregate `oneose`**: a failed connection calls `handleClose` → `handleEose`, so offline fires in ~19 ms and reports a cleared library as fact. The rule is `event_in_hand or (reached > 0 and answered == reached)`, per relay, never-connected relays excluded; any new query passes `syntheticEoseTimeoutFor(maxWait)`. Pinned by `check:readtrust`. → [`docs/nostr.md`](docs/nostr.md)
- **A relay that CONNECTS and then answers nothing costs every query its full ceiling, so adding one to any relay list is a latency decision.** Queries resolve at **aggregate** EOSE, which a silent relay never sends, and `assembleNotes` runs six in series: three such relays measured 42,037 ms, trimmed to 8,413 ms. **Two rules:** *adding* a relay requires measuring what it ANSWERS with this app's own filters; *every broad scan* passes `FEED_QUIET_MS` (it fires on silence, never on slowness, and leaves `allEosed` FALSE), except a deep link that must find ONE event. → [`docs/nostr.md`](docs/nostr.md)
- **Read a shared list from the relays you WRITE it to, and treat a missing publish set as a reason to WAIT, never to narrow.** Favorites and mutes read-merge-republish to `resolvePublishRelays` (the NIP-65 write set unioned with `DEFAULT_RELAYS`); for an event this app wrote that read is a SUBSET of the publish set and normally finds it, so this is an invariant, not the explanation for a list going missing. Four cases survive: another app is the writer, the 20 cap, partial acceptance, a `bmb:relays` override. → [`docs/nostr.md`](docs/nostr.md)

### Favorites (kind:10333) — a shared event with no undo

One replaceable event, many writer apps, no partial update, no history. **A wrong publish deletes another app's data on someone else's device, silently, with no undo** — which is why this area has its own doc and its own check script.

**Editing `lib/nostr/favorites-*.ts` requires [`docs/nostr.md`](docs/nostr.md) first.** Fourteen rules live wholly inside those modules, each pinned by `check:favsync`, none reconstructible from the source, and every one has already shipped wrong. The ones to hold in mind: `content` is **CARRIED** byte for byte; **tag order IS the data**, and so is the whole `i` **tag**, so the merge edits an ordered node list and never rebuilds `['i', id]`; **an entry is told apart by LENGTH, never position 1** (`entryKind`); a **claim on an item is the PAIR** (`itemClaim`); the **baseline describes BOTH halves** every cycle; **`seedFavoritesMode` fails closed** on an ambiguous wire, never an EMPTY one; **`favCleared`** alone separates a deliberate clear-all from an unhydrated store; **carry what you can't read**.

**The feed-guid migration is a DEPLOY-ORDER fact:** this app reads AND writes the three-element item tag (stages 2 + 4), so **a StableKraft on stage 0 turns every saved episode into a followed show until it ships**. Stage 3 is not done: a placement feed entry already on the wire is carried, never retracted. `check:conformance` is **28 green / 3 red on purpose** (`scripts/conformance.mjs` says why); a NEW red is a regression.

These seven you can break from an unrelated file:

- **Favorites are ONE plain replaceable event at `kind:10333`: read → merge → publish, always, and never on a degraded read.** The read passes `dTag: ''` to `acceptsEvent` (no `d` tag, or an addressable event sharing the kind gets laundered in) and `syncFavorites` is the only writer. **The wire format is an external spec and is NOT ours to change** ([PC20-Nostr](https://github.com/ChadFarrow/PC20-Nostr/blob/main/pc20-favorites.md)): a format change is a PR there first. `PRIVATE_FAVORITES_ENABLED` is **true**; that gate stops you CHOOSING private and **must gate nothing else**.
- **`setFavorites`/`setFavoriteEpisodes` write THROUGH to localStorage, and that cache is an INPUT to the next hydrate — so plan before you paint, and never paint a merge the planner refused.** `cached[feed.feedGuid]` alone tells a real album favorite from a group opened to place a track. **The store renders BOTH halves and publishes ONE**: `claimedByBaseline` decides what leaves the inactive half (adopting more is a private→public **disclosure**), and what it excludes is `carried` — rendered, never published.
- **A refusal from the favorites cycle is a `null`, NOT a throw — a caller that acts on success must test the return value.** `syncFavorites` returns `null` *without recording anything* on a degraded read, `'wholesale-delete'`, `'mass-removal'`, `'create-held'`, `'private-unreadable'`, `'private-too-large'`, and when the publish reached no relay, so `await` looks like success. The privacy dialog discarded it and reported entries taken down while they sat on the relays, **and `'off'` then stops `runHydrate` and `requestFavoritesSync`.**
- **Where a favorite goes is asked ONCE, in `requestFavoritesSync`, through ONE module-level slot — and "never chosen" is a real state that must not be defaulted.** `storage.favPrivacy:<npub>` is `'public' | 'private' | 'off'` or absent; flattening absent to `'public'` publishes before the user was offered the choice, and a relay cannot be asked to forget bytes. **`onFavoritesModeNeeded` holds one callback that exists only while its registrant is mounted** (it lived in `<AppHeader>` while `<Player>` is in the ROOT LAYOUT, so a ♡ on `/npub/<npub>` reached no relay). **`'off'` never deletes**; offering `withdrawThisDevice` is a question about the **BASELINE, not the mode**.
- **Never offer a favorite whose PARENT FEED can't resolve — and "not resolved yet" is not "will never resolve".** A host may point a `<podcast:valueTimeSplit>` at a **publisher** feed, so the row looks resolved while its `feedGuid` names something `/episodes/byguid` will never take. `ValueTimeSplit.parentFeedGuid` is `undefined`, a string, or `null` (**known unresolvable, render no heart**); ask `/api/remote-item`, withhold the heart until it answers, release it on a FAILED lookup.
- **A sign-in must paint the account's caches into the store BEFORE hydration runs, and `<NostrAuth>`'s page-load restore effect is not that path** (it early-returns on `if (identity) return;`): an explicit sign-in painted nothing, handing `hydrateFavorites` an empty `local` beside a full baseline, which satisfies the removal test for every entry at once. Favorites UNION the store; mutes replace.
- **`["visibility",…]` states which half the list lives in, and omitting `stating` from a `planFavoritesPublish` call RETRACTS it** — `tagsFromList` rebuilds it from the model, so a caller that says nothing withdraws a mode another app stated (default: `statedVisibility(readTags)`). `<FavoritesHydrator>` proved it, turning every hydrate on a stated list into a `wholesale-delete`. `effectiveListMode` is the ONE decision, and the tag goes on the EVENT, never inside `privateTags`. → [`docs/nostr.md`](docs/nostr.md)
- **A guard that silently withholds must say so.** The degraded-read branch kept local state, published nothing, announced nothing, read as "your favorites are gone", and nearly got reverted for causing the bug it prevented. A new "we couldn't verify this, so we're doing nothing" path needs a user-visible state, not a `console.warn` (`favoritesSync`, `<FavoritesSyncNotice>`), **and it must RETRY itself** — on a phone the radio is late, not broken: `startFavoritesReadRetry` retries only the reasonless degradation (`favoritesReadRetryable`).

### Reads, routes and the read index

- **An accelerator is never an authority — `null` means "no answer", never "there are none".** `lib/playlist-db.ts` too: a MISS is harmless and a HIT is NOT, because `payableValue` reads `episode.value` first, so a stale cached block outranks the live feed and carries NO payee (`withoutStoredValue`; a surface boosting a STORED episode reloads it from its feed first, `<HistoryBoostButton>`). **The read index never holds kind:10333, 10000, 3, 30078 or 4/1059** (`ingest.ts`'s `FORBIDDEN_KINDS`: a filter is a *request*, and a relay may send anything). Every fetcher in `lib/nostr/index-client.ts` returns `null` for an EMPTY result, the proxy answers 503 never an empty body, the three sources union rather than replace, and a time-sensitive kind needs a freshness gate. → [`docs/nostr.md`](docs/nostr.md), [`docs/feeds.md`](docs/feeds.md)
- **An empty library is a CLAIM — a surface may only make it once the read has answered, and "still loading" (`'loading'`, `'idle'`) is not "nothing there".** `<FavoritesPage>` once told a signed-in user whose read hadn't landed **"Nothing saved yet."** over a full library; signed out is excluded on purpose. → [`docs/ui.md`](docs/ui.md)
- **`selectPodcast` / `openEpisode` / `discussionEpisode` are read by `<HomePage>`, which renders at `/` ONLY — a component calling them from a standalone route changes nothing you can see.** `<NoteCard>`'s "→ show · episode" line did nothing, with no error, on the npub page; `openShow` now navigates to `/` when the pathname isn't already there. → [`docs/nostr.md`](docs/nostr.md)
- **A Podcasting 2.0 PLAYLIST is any `*L` medium, and "is this a playlist" is not "are its rows tracks".** `LIST_MEDIUMS` (`lib/util.ts`) is an **allowlist**, never `endsWith('l')`; `isPlaylistMedium` decides how a feed PAGES and `playsAsTracks` how a ROW behaves (`music`/`musicL` only) — collapsing them turns every `podcastL` into a jukebox. → [`docs/feeds.md`](docs/feeds.md)
- **Resolving a LIST of anything goes through the batch door, never a `Promise.all` over the single-item one** (`<Podroll>` made 13 requests for 12 entries, now 2). **Warm first** (`warmPodcastCache`/`warmEpisodeCache`), **then keep the resolve pass**: a "not found" guid still falls back to its `feedUrl` hint. → [`docs/feeds.md`](docs/feeds.md)
- **A surface resolving MANY authors uses `fetchProfilesFor` (`lib/nostr/discover.ts`), never a `fetchProfile` per pubkey** — that opens **a subscription per relay**, and relays cap subscriptions per connection and drop the overflow **silently** (`<NostrLiveStreams>`' 21st host never got a live event). **No stage may sit behind an `await` it has no relationship with** (`assembleNotes` fetched kind:0 after awaiting the reply forest). → [`docs/nostr.md`](docs/nostr.md)
- **`mergeNotes` merges the two copies of a note FIELD BY FIELD — never replace on id**: the index and relay passes carry different enrichment, and losing `isBoost` takes the note off the feed. **Render through `visibleNotes`**, which also drops a bot's copy of a boost the sender posted. → [`docs/nostr.md`](docs/nostr.md)
- **A route that answers with `s-maxage` and no `max-age` has the browser re-download what the CDN already holds** — worst for `/api/feed`. A private cache SHORTER than the shared one adds no new staleness; live status is not read from it (`/api/live-status` polls at `max-age=10`) and `/api/episode-by-guid` is left alone (the client holds those seven days). → [`docs/feeds.md`](docs/feeds.md)
- **`/api/feed` is requested from ONE place in the browser — `loadFeed` (`lib/podcast-meta.ts`)**, which builds the URL and coalesces an in-flight request (a cold deep link downloaded the feed TWICE). **Nothing is cached past the promise settling**, or the next navigation sees a stale list. → [`docs/ui.md`](docs/ui.md)
- **A URL deep link must not pay for the page it is not going to show**: `inDetailView` (`!!selectedPodcast`) is not set until a `?podcast=` restore resolves, so `entryResolved` gates `<NostrLiveStreams>` and `<GlobalNostrFeed>` — **false on the server and the first client render, set when the restore FAILS too, never cleared.** → [`docs/ui.md`](docs/ui.md)
- **The read index caches Podcast Index's RAW record, so every reader must normalize it — `podcastFromPiFeed` / `episodeFromPiRecord` (`lib/pi.ts`), never a bare `askIndex<Record<string, Podcast>>`**: that generic type-checks and is wrong in every derived field, and it would carry PI's `value` past the RSS-only rule. It needs the index configured AND warm, so it never reproduces locally and no `check:*` pins it. A record that fails to normalize is left **absent**, never `null`. → [`docs/feeds.md`](docs/feeds.md)
- **A cap on the ITEM COUNT is not a cap on the FAN-OUT, and capped walks NEST.** `resolveValueTimeSplits` (200) calls `resolveRemoteItemFromRss` (100), both "bounded", both starting everything at once: 20,000 concurrent 8 MB-capped fetches from one request. Bound the concurrency with `mapLimit` — that number composes and a count does not: `PI_FANOUT` where Podcast Index is being protected, `FEED_FANOUT` where our own heap is. → [`docs/security.md`](docs/security.md)
- **New API route starts with `rateLimit(req, '<route>', N)`** and sets `Cache-Control` on **200 responses only**. Returns `{ error }` via `getErrorMessage(e, fallback)`.

### Storage and module graph

- **All `bmb:*` access goes through the typed helpers in `lib/storage.ts`** — never `localStorage.getItem`/`setItem` **or `sessionStorage.*`** anywhere else (`bmb:nwc_uri_sess:<npub>` holds a spending credential and once had its key hand-written in four places). New persisted field ⇒ new accessor. → [`docs/storage.md`](docs/storage.md)
- **A cache write that did not reach disk must not leave its baseline behind.** `safeSet` returns whether the value persisted and `storage.favorites.set` returns it too — **don't drop that answer**. `dropBaselineIfWriteFailed` (`lib/store.ts`) covers a **stale** non-empty cache that `trustedBaseline` cannot see. **It clears the PUBLIC half only**: writing the two-field literal disowned every private claim, leaving those entries unremovable behind a heart that still rendered. → [`docs/storage.md`](docs/storage.md)
- **`lib/storage.ts` sits UNDER `lib/nostr/`, and the graph is CLEAN — keep it that way.** One value import used to close `storage → auth → signer → amber → storage`; it moved into the import-free leaf `lib/nostr/profile-metadata.ts`, which is why `lib/nostr/amber.ts` may import `lib/storage.ts`. **`npm run check:amber` asserts there is no value-import path from `lib/storage.ts` into `lib/nostr/{amber,auth,signer}.ts`**: a cycle does not fail the build, it shows up as an export that exists reading `undefined`. Push shared things DOWN into an import-free leaf.
- **Feed artwork must never outrank the enclosure, and both art surfaces must share one gate.** Chapter art is arbitrary third-party media, often on the **same origin as the audio** and enormous (20–36 MB GIFs against a 175 MB mp3 on one connection); a starved element keeps `paused === false`, so the transport showed ❚❚ over silence. `<Player>`'s `artOk` is the gate and `nowPlayingArt(…)` is what both surfaces render. **`waiting`/`stalled` MEASURE the buffer, never assert starvation**; **closing is cheap, reopening is not**. → [`docs/ui.md`](docs/ui.md)

## Boost flow invariants

`components/boost-modal/index.tsx` orchestrates; `lib/v4v/boost.ts` is the engine. Reasoning for all of it is in [`docs/money-boosts.md`](docs/money-boosts.md).

0. **A live-stream boost pays like every other boost — `sendBoost`, keysend or LNURL, never a zap** (invariant 12). **The payee is the HOST's kind:0 `lud16`, and a degraded read of it FAILS CLOSED** (`resolveStreamV4V` returns `{ value, trustworthy }`): the no-address arm pays the event AUTHOR, which on a platform-published broadcast is the platform's bot key (measured on zap.stream). `liveValueState` stops the button claiming a block does not exist. → [`docs/nostr.md`](docs/nostr.md)
0.5. **A boost pressed inside a `<podcast:valueTimeSplit>` window pays the TRACK, in two legs.** `useActiveSplit` resolves it, `splitTrackAndHost` divides it, and `sendBoost` runs twice, sequentially, both boostagrams carrying the track's `remote_feed_guid`/`remote_item_guid`. Six rules, each a way to pay the wrong person or lie about having paid:
    - **The target FREEZES at modal open** — the episode keeps playing while the user picks an amount.
    - **`positionSec > 0` is the "is this episode actually playing" test** — a split authored at `startTime: 0` otherwise redirects a boost pressed from a list row.
    - **The send button is DISABLED while the split resolves** — a money gate, not a spinner.
    - **BOTH halves go through `redirectLegs`, and `payable` is the send gate — never `sats > 0`.** `splitSats` returns 0 for an unreachable payee and `payOne` short-circuits `sats <= 0` to `ok: true` **without contacting anyone**, so a ✓ and a `StoredBoost` appear for a payment nobody attempted. The dropped payee is **named on screen**.
    - **The host leg is non-fatal and never merged into the track block**; an unresolvable remote item falls back to the show's block **and says so on screen**.
    - **`fireConfetti`/`playBoostSound` fire ONCE, after BOTH blocks settle** (`primeBoostSound` stays synchronous in the click handler); **one `StoredBoost` and one note**.
1. **Lightning first, then Nostr.** `publishBoostNote` fires only after `sendBoost` returns *and* `collected.some(r => r.ok)`; inverting publishes false "I boosted" notes when every payment fails. **A site-signed note then pays its stamp, 1% of the boost** (`payStampInvoice`), never retried; a failed stamp posts it from a one-time key. → [`docs/money-boosts.md`](docs/money-boosts.md)
2. **`pickRail()` = a CONNECTED rail's pref first, then NWC > Spark > WebLN**; WebLN counts as connected once ENABLED, as the chip shows. `storage.railPref.set/clear` notify `subscribeRailPref`.
3. **Only an RSS document names a payee.** `buildPodcast` and `buildEpisode` take no payee from PI's `value` or `timesplits`, and the playlist database maps no value column — never add one back. `/api/feed` calls `feedItemValue` (`check:musicl`). **A row with no `value` key is NOT READ, never "none"** (`valueNotRead`): `<Player>`, a row's BOOST and the episode page ask `/api/item-value`. → [`docs/feeds.md`](docs/feeds.md)
4. **Splits use weights, not percentages** (`ValueRecipient.split`; total weight is the denominator). `splitSats()` (`lib/util.ts`) is **largest-remainder (Hamilton)** and gives every positive-weight recipient **at least 1 sat** — floor-then-dump-the-remainder sends a 98/1/1 block's whole 100 to the artist. **A 0-sat leg is `ok: true` in `payOne`**, so a caller splitting a DERIVED amount goes through `payableSplit`.
5. **TLV record `7629169` only**, with `sender_id` inside the boostagram JSON. We do **not** also emit a `696969` sender record — that key collides with shared-node sub-account routing. Per-recipient `customKey`/`customValue` IS attached.
6. **WebLN `customRecords` are plain JSON, not hex** (providers hex-encode internally; pre-hexing makes Helipad's `JSON.parse` fail). NWC's `pay_keysend` is the opposite: `tlvHexFor` (NWC) and `recordsForKeysend` (WebLN) are different wire formats.
7. **Note amount is intent, not actual.** `formatContent` and the `amount` tag use `boostagram.value_msat_total`, not the sum of successful legs; the partial breakdown is in the modal and Helipad.
8. **BoostBox is LNURL-only.** `lib/v4v/boostbox.ts` POSTs metadata *before* `fetchLnInvoice`, then puts the returned `desc` in the LUD-21 `comment`; a failure is non-fatal. **The desc and the typed message go to `fetchLnInvoice` as SEPARATE args, never pre-joined** (`buildLnurlComment` keeps the desc whole or drops it), and **`desc` is NOT the descriptor alone** (a BOLT11 description budgeted against 639 chars): `descriptorOnly` recovers the two spec tokens by SHAPE, never by `endsWith(message)`, because a recipient's `commentAllowed` is routinely 255. → [`docs/money-boosts.md`](docs/money-boosts.md)
9. **LNURL invoices are amount-verified before paying.** `fetchLnInvoice` and `sendZap` decode the returned BOLT11 via `bolt11AmountMsat` (`lib/v4v/bolt11.ts`) and throw on an amountless invoice or any mismatch — a malicious LNURL server can't substitute a larger one.
10. **Payment order IS display order — `sendBoost` traverses `recipientOrder(recipients)`,** biggest share first, as `<SplitsPreview>` renders (feed order is authoring order: a live block settled four 1-sat payees with a ✓ ahead of the artist at 94.1%).
    - **It reorders the TRAVERSAL, never the array.** `recipients`, `splits` and `results` stay positionally coupled, and `results` is **pre-sized and assigned by index** — `results.push(r)` type-checks and builds while pairing every leg with the wrong recipient.
    - **`onProgress` reports the recipient's index, not the settle sequence**; the modal's `results` is `(BoostResult | undefined)[]` and the union is load-bearing.
    - **Leg STARTS stay sequential — never parallelize.** Only WAITING overlaps: the single BOOST panel's NWC `moveOnAfterMs` (`payInOrder`).
11. **A wallet that never answered did NOT fail — never report it as one, and never retry it blind.** The Alby SDK throws `Nip47ReplyTimeoutError` after 60 s, but the request was published and the wallet may have paid. `mapNwcError` makes it `NwcIndeterminateError`, `payOne` sets `BoostResult.indeterminate`, and every consumer renders `?`, never `✗`; only `resendLeg` pays one again — the SAME hash, once `lookup_invoice` says `failed`. **Losing sats is recoverable; sending them twice is not.**
    - **Two retry arms, two functions, two vector sets — never merge them.** `NwcNotAttemptedError` (`NOT_IMPLEMENTED`, `UNAUTHORIZED`, `RESTRICTED`) proves nothing moved and is the only thing `payOne` may retry over LNURL; `routingFailureProvesUnpaid` reads the failure REASON on an allowlist. Widening either to a timeout, or to the `PAYMENT_FAILED` **code**, is a double-pay. `failureBlamesDestination` answers *whose fault*, never *did the sats move*.
    - **Match the leaf class, not `Nip47TimeoutError`** — `Nip47PublishTimeoutError` shares that parent and means the opposite.
    - **Streaming deliberately still counts it as a failure** — the safe direction for an unattended payer. → [`docs/money-boosts.md`](docs/money-boosts.md)

12. **A value-block leg is NEVER a zap — it pays by keysend (TLV `7629169`) or LNURL (BoostBox descriptor); a zap is a BOLT11 with neither (Helipad showed "Lightning Invoice"). The note QUOTES ONE kind:9735, the SITE-signed summary for the sats that settled** (`/api/nostr/zap-receipt-sign` derives it from a signed 9734, never from caller tags), as `q` AND body `nostr:nevent` — Fountain lists off the tag, draws the figure off the body, and renders the FIRST quote only. The summary goes out on `shareNostr` alone; a live stream's kind:1311 chat line is gated on `shareNostr && shareAs === 'self'`, never `!anonymous`. `sendBoost` has no `zap` option; `check:zapreceipt` scans for one. → [`docs/money-boosts.md`](docs/money-boosts.md)

**Anonymity applies to the payment, not just the Nostr note — and to EVERY identity field.** With the share picker's **"Anonymous"** active (`anonymous = !!identity && shareNostr && shareAs === 'site'`), every boostagram **omits** `sender_id` (the pubkey, which aggregators resolve to a profile) and `reply_address`, and **replaces** `sender_name` (recipients display it verbatim and `formatContent` prints it into the note; omitting it would leave presentation to each aggregator).

**`DEFAULT_SENDER_NAME` (`BRAND.senderName`, in `lib/brand.ts`) is a real default, not the input's ghost text.** Both modals call `resolveSenderName(typed, anonymous)` for an anonymous boost and for an empty "From"; one const feeds every wire site (the boostagram legs, the local `StoredBoost`, `BoostAllModal`'s summary), so **don't reintroduce a bare `name` at one**. The typed value stays in parent state and `storage.senderName` persists the **typed** name only.

**`anonymous` is gated on `identity`**, because `bmb:share_nostr_as` is a single global key and an ungated flag would silently replace a signed-out user's name with the default. **There is ONE definition of it, in `useSharePicker` (`components/boost-modal/use-share-picker.ts`); a new boost surface uses that hook** — both modals carried their own copy, which is how this promise was broken twice. `senderName` is deliberately not centralized (it needs each modal's own "From" state).

## Streaming sats — money invariants

The engine is `lib/v4v/streaming.ts` + `lib/v4v/stream-ledger.ts`. **Off by default.** Full reasoning in [`docs/streaming.md`](docs/streaming.md). **Every rule here follows from one property: this spends money unattended, on a timer, with no confirmation step** — a mistake has no screen in front of it to be noticed on.

- **It is not a new payment path.** Settlement calls the same `sendBoost()` with an unattended `action`; rails, splits, TLV and the lnaddress→keysend upgrade are untouched.
- **`action` is per LEG — `streamAction` (`lib/util.ts`) returns `'auto'` when the leg pays a SONG and `'stream'` when it pays the SHOW.** `<podcast:medium>` finds no music show and an open `<podcast:valueTimeSplit>` is not a song; the live signal is Split Kit's block stamp `'music'`, never its presence. `lib/v4v/boostbox.ts` must keep downgrading `'auto'` → `'stream'` for LNURL legs, whose enum rejects `'auto'` silently. Pinned by `check:vts`.
- **The ledger is debited BEFORE the payment is awaited** — crediting after leaves the same sats for the next tick to spend again. **The double-pay guards live on the LEDGER, not the context**: the context is rebuilt on every reload and Fast Refresh while the balance is restored from `bmb:stream_pending`.
- **Settles are serialized** through a promise `chain`; never parallelize legs or settles.
- **Elapsed time is `min(wall-clock delta, playback-position delta)`, capped at 5 min** — wall alone bills a sleeping laptop, position alone a forward seek.
- **A batch below `max(10, recipientCount)` sats carries instead of sending — even when forced.** **Two consecutive failed settles stop streaming for that item.**
- **A failed settle does NOT license the claim "nothing was sent" — derive it** (`sentClause` in `components/streaming-settings.tsx`, off `StreamingStatus.lastErrorSentSats` + `lastErrorIndeterminate`): a force settle returns a `runs` **array**, so bucket 1 can pay while bucket 2 fails. **Telling someone they still have sats they have already spent is the one error re-boosting cannot undo.**
- **`stopStreamingEngine` persists but does NOT settle** — `<Player>`'s cleanup runs on every Fast Refresh, so a settling teardown would fire a real payment when a comment is edited in dev.
- **No kind:1 note, no confetti, no `playBoostSound`.** **The one exemption is a kind:3369 value-playback receipt: no client renders that kind, so it cannot reach anybody's feed.** Off by default (`bmb:stream_receipts`); it publishes NOTHING when Anonymous is set (the signature IS the pubkey) or under a signer that would prompt or hang (`canSignUnattended`), is never awaited by the settle `chain`, and **a failed publish must never reach `noteFailure`**. → [`docs/value-playback.md`](docs/value-playback.md)
- **A kind:33369 summary is DERIVED, never accumulated.** It is ADDRESSABLE, so one person in two apps is two writers at one address. **Monotonic** (`>=` on BOTH fields); **changed BY VALUE, never by bytes**; **never publish on a read you cannot trust** (stricter for a SUM than `readIsTrustworthy`'s usual answer). Off by default (`bmb:stream_summaries`), separately from receipts because a summary sits at a stable guessable address. Pinned by `check:vpsummary`. → [`docs/value-playback.md`](docs/value-playback.md)
- **Logs to `bmb:streamed:<npub>`, never `bmb:boosts:*`** — that log is capped and rendered into the user's feed, and six settlements an hour would evict real boosts within a day. **`sender_id` honors the same anonymity signal as the boost modal.**
- **"May we publish?" is NOT `!streamingIsAnonymous()`.** That predicate answers a question about ATTRIBUTION, and "Don't post" leaves `shareNostrAs` alone, so it makes the predicate FALSE — gating a receipt on its negation published signed, public records for the user who chose to publish *less*. The gate is `streamingMayPublish()` = `shareNostr && shareNostrAs !== 'site'`. → [`docs/value-playback.md`](docs/value-playback.md)
- **`crypto.randomUUID` is SECURE-CONTEXT-ONLY — use `randomId()` (`lib/util.ts`) anywhere a throw isn't already caught.** Over `http://<LAN-IP>` (how this app is tested on a phone) a bare call throws, and `openContext` runs from the bare `setInterval(tick)` callback — an unattended payer that silently does not exist. `randomId` is **never for anything where unpredictability is a security property**.

## v4v-toolkit swap-out boundary

`lib/v4v/*` and `lib/nostr/` are the only files that talk to wallets/signers. Components reach them through a small surface — `lib/v4v/boost.ts` (orchestrator), `nwc-state.ts` (`nwc.ts` only via `import()`), `spark.ts`, `webln.ts`, `wallets.ts`, `zap.ts`, `streaming.ts`, `stream-ledger.ts`, `live-value.ts`, the `lib/nostr/` barrel and `lib/nostr/google-auth` — so a toolkit swap touches neither `components/` nor `app/`.

**The arrow only points one way: `lib/v4v/` never imports from `components/`.** `DEFAULT_SENDER_NAME` once broke it. → [`docs/money-boosts.md`](docs/money-boosts.md)

**`lib/util.ts` is where the pure money ARITHMETIC lives, and `lib/v4v/` is where money MOVES** (`recipientOrder`, `storedBoostLegs`, `splitSats`, `splitAtPosition`, `splitTrackAndHost`, `payableSplit`; `boost.ts` re-exports `splitSats`). The line is what makes the arithmetic **testable**: `lib/util.ts` loads under `node --experimental-strip-types`, so `check:vts` imports the shipping functions rather than a copy, and `<SplitsPreview>` and `<ValueSplitRows>` render an allocation without importing a wallet. **A new pure split/order/allocation helper belongs here, not in `lib/v4v/`.**

**`lib/util.ts`'s import line is load-bearing — keep it type-only.** Every non-type import silently un-pins everything the check scripts reach through this file. It also holds non-money helpers on the same terms: `compareEpisodeOrder` (`lib/pi.ts` and `app/api/feed/route.ts` each had a copy), `showShareUrl` (the episode list and the fullscreen player built *different URLs for the same show*), and the artwork-proxy group `artWidth`/`artCandidates`/`artProxyUrl`/`artTypeVerdict`, shared by a server route and a client component that must agree about the width allowlist.

## State + persistence

Zustand store (`lib/store.ts`), **in-memory only** — `identity`, `current`, `favorites`, `favoriteEpisodes`, `mutedPubkeys` and the lifted flags (`signInOpen`, `walletOpen`, …) that let a surface which doesn't own a modal open it. `favoritesSync` is one status, not one per list; `'idle'` is the pre-hydration and signed-out state, never a failure. `artOk` is `<Player>`'s artwork gate and it is its only writer; `seekReq` (`{ t, n }`) is consumed by `<Player>`.

**`favorites` and `favoriteEpisodes` are the source of truth for what gets published, not a render cache.** Every id on the merged list gets a row whether or not Podcast Index resolved it: building the maps from resolved entries only let a PI outage prune the store while the baseline still named the un-pruned set, so the next load published every unresolved entry as a removal. `addedAt: 0` means "not known yet". → [`docs/nostr.md`](docs/nostr.md)

Everything else lives in `localStorage` and is never sent server-side.

**`safeSet` must never silently swallow a failed write.** A settings control here has no local state — it writes through `storage` and renders whatever reads back, so a discarded write **freezes the control**: tap it, nothing moves, no error anywhere. That shipped, reported as *"I can't turn on streaming sats in Safari on iOS"*. Two causes, both silent on iOS Safari: a full store (`QuotaExceededError` down to a one-byte `bmb:stream_on`, while reads keep working, so a fresh profile never reproduces it) and a blocked store (`SecurityError`, which freeing space cannot help). `safeSet` returns whether the value reached disk, evicts one cache namespace at a time in `EVICTABLE_PREFIXES` order, and falls back to `memoryMirror`. **A cache never displaces a setting; a setting always displaces a cache.** → [`docs/storage.md`](docs/storage.md)

## Background art and the canvas-bg gotcha

`app/layout.tsx` renders `public/hero.jpg` as a fixed full-viewport layer with a `bg-ink/75` overlay and `<Image fill priority />`. Same image doubles as the OG image.

- **The page background is set in CSS (`app/globals.css`, on `html, body`), never as a Tailwind class on `<body>`.** A background applied to `<body>` in the JSX propagates to the canvas and paints over the fixed image layer regardless of z-index — the hero breaks with no errors, just a flat-color page.
- **`html, body` use `overflow-x: clip`, NOT `hidden`.** `hidden` computes `overflow-y` to `auto`, turning html/body into a scroll container that traps `position: sticky` descendants.
- **An overlay locks the page behind it with `lockScroll()` (`lib/scroll-lock.ts`) and NEVER with a local `overflow: hidden`**: on iOS a document scroll in the installed app carries every `position: fixed` element with it and the overlay slides off the screen. **The refcount is app-wide, not per surface** (a BOOST modal opens from inside `<FullscreenPlayer>`, so overlays stack). Each overlay's scroll boundary also carries `overscroll-contain`.
- **Every modal — and any page-level dropdown — renders through `<ModalShell>` (`components/modal-shell.tsx`) and portals to `document.body`**: the layout's `relative z-0` is a stacking context, so a `fixed` overlay inside a page can never outrank `<TabBar>`'s `z-30`. Pass `dismissable={false}` while a payment is in flight and `closeButton` for its ×; a bottom-anchored element clears the dock with `--dock-b` and `translateY(var(--kb-inset))`, never a literal. **An overlay is `fixed inset-x-0 top-0 h-[100dvh]`, never `inset-0`; its card caps at `max-h-full`, never `max-h-[92vh]`; a pane inside is `h-full`, never `calc(100vh - <header>)`.** → [`docs/ui.md`](docs/ui.md)
- **`z-[70]` is the app's ceiling and it belongs to the iOS status-bar strip (`app/layout.tsx`) — nothing may outrank it.** `appleWebApp.statusBarStyle` is `black-translucent`, so iOS paints the clock and battery in WHITE regardless of `theme-color`, and in light mode `--ink` is cream — the strip is the only thing keeping the status bar legible in the installed app. It is `env(safe-area-inset-top)` tall, so it is **0px and invisible everywhere you would be testing a new overlay**. It sits above `<ModalShell>`'s `z-[60]` and `<FullscreenPlayer>`'s `z-50` deliberately: both paint `bg-ink`, so a strip underneath them is covered exactly when a modal is open.
- **A full-height overlay needs the SAFE-AREA inset, not just `100dvh`.** `viewportFit: 'cover'` starts the box at the physical top of the screen, so `<ModalShell>`'s `p-4` put a `max-h-full` card's header under the notch. The block axis is `max(1rem, env(safe-area-inset-*))` — **`max()`, never a sum**, or every notched phone gets a further notch's worth of padding for nothing. → [`docs/ui.md`](docs/ui.md)

## Styling tokens

Custom palette in `tailwind.config.ts` — don't introduce new colors without adding them here: `ink` (page bg), `bone` (primary fg), `bolt` (Lightning yellow), `nostr` (magenta), `muted` (secondary), `line` (borders), `nick-0`…`nick-9` (IRC names, `nickColor`). Fonts: `font-display` (Bricolage Grotesque), `font-mono` (JetBrains Mono).

**Fonts are loaded by `next/font` in `app/layout.tsx` and reached through `var(--font-display)` / `var(--font-mono)` — never name the family literally, and NEVER add an `@import` to `app/globals.css`**: an `@import` serializes the critical path four hops across three origins, and a literal family name bypasses the size-adjusted fallback that stops `display: swap` shifting layout. Three places move together: the two `next/font` calls in `app/layout.tsx`, `fontFamily` in `tailwind.config.ts`, and the two raw declarations in `globals.css`.

Reusable element classes — `.card`, `.btn`, `.btn-bolt`, `.btn-ghost`, `.btn-mini`, `.btn-inline`, `.tile`, `.input`, `.stamp`, `.headline`, `.seek` — are defined in `app/globals.css`. Read that before inventing new ones.

The sort is stable, and since `sendBoost` traverses by it and `storedBoostLegs` writes history by it, that is a payment-determinism guarantee: no fee-awareness, no opt-out.
- **A sent boost's `StoredBoost.legs` are built by `storedBoostLegs(results)`** — three sites hand-rolled the identical map. Biggest-share-first, because `legs` are read verbatim and a stored leg carries **no `split` weight**, so whatever order is written is permanent. Boosts stored before this keep feed order; **deliberately not migrated**.
- **`components/lists.tsx` is a BARREL — put new list code in `components/lists/`** (re-growing it is how it reached 1192 lines). **The hearts live in `components/fav-heart.tsx`** and are only re-exported here: `podroll.tsx` importing them from `lists.tsx` while `lists.tsx` imports `<Podroll>` was the original module cycle.

- **The page header is `<AppHeader>`, shared by `/` and `/favorites`; NOTHING you add to it may exceed 38px tall.** `--app-header-h` is a hard-coded 71px and `<EpisodeList>` pins against it, so a taller control breaks the OTHER route's sticky offset; at 390px the wordmark needs 142px of a 141.6px box, so a right-hand control must buy its width back below `sm:`. All three halves or none.
- **`showShareUrl` (`lib/util.ts`) targets the site ROOT, never `window.location.pathname`** — `?podcast=` is restored only by `<HomePage>`'s mount effect, which runs on `/` alone, while `<FullscreenPlayer>` is live on every route. **Its optional `episodeGuid` makes a DIFFERENT destination**, so a surface presenting both renders both buttons and names each target (`<ShareTargets>`). → [`docs/ui.md`](docs/ui.md)
- **A per-track control binds to a `<podcast:valueTimeSplit>` window, never to a chapter** — the two render in ONE list, but `mergeEpisodeContents` (`lib/util.ts`) never maps a chapter to a window (they can OVERLAP: on Homegrown Hits 146 the covering window names the wrong track). `check:vts` pins that **only a chapter may be dropped** and that dedupe is **on a tolerance, not equality** (PI returns integer `startTime`s). **"This episode isn't playing" is `currentSec={undefined}`, never `0`** (the interval is half-open). → [`docs/ui.md`](docs/ui.md)
- **A LIVE show's track hearts come from the played log, and the log is guid-scoped** (`lib/live-played.ts`, `<LivePlayedTracks>`): every row carries a working heart, so `livePlayedSnapshot(guid)` makes the caller name the item. A `null` target means the watcher detached, not that the songs never happened; `recordLivePlay` sits in `setTarget`, the one funnel; **blocks are judged on their IDENTIFIERS, never `blockType` alone** (`isNotPlayed`). → [`docs/streaming.md`](docs/streaming.md)
- **A control must LOOK like one before it is touched: a bordered chip (`.btn-mini` and up) standing alone, `.btn-inline`'s permanent underline inside a sentence — never bare `text-muted` that signals only on `hover:`.** A phone has no hover, so that is no affordance at all; 25 controls had drifted into three spellings. → [`docs/ui.md`](docs/ui.md)
- **A control is at least 24×24 CSS pixels, and a heading that folds something IS a control** (WCAG 2.5.8; a link inside a sentence is exempt). The violation is invisible in review — the element looks right but has no vertical padding: `<CollapsibleHeading>` shipped at **16.5px**.
